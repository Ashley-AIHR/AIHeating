# Orbitable engineering demonstrator

Implemented 12–13 September 2026 following the user's approval to use professional public CAD/BIM assets for a **clearly labelled engineering demonstrator**. The imagery release remains available at `/reference`; it was not passed off as reconstructed geometry.

## Actual engineering functions

The default workspace loads source-derived GLB meshes, supports full camera orbit/pan/zoom, focuses or isolates a selected component, hides assets, clips the scene with X/Y/Z planes, and measures 3D surface-to-surface chords by raycasting actual mesh triangles. Source GlobalIds, EXPRESS IDs, IFC classes and property sets remain inspectable. Camera viewpoints, source-bound review notes and measurement coordinates can be exported with a source checksum.

The district tab loads published pipe identities, endpoints, lengths, internal diameters, insulation thickness and roughness. A length-weighted shortest-path tool traces an intact-network route from a heat source to the selected pipe. A separate multi-edge outage screen compares baseline and post-removal graph connectivity to the two sources. A substation is counted if it previously had both supply and return connectivity and loses either after removal.

These are useful model-review and topology-audit operations, not automatic operational approval. The outage graph is undirected and has no valve inventory, pressure calculation, flow redistribution or thermal rollout. A graph cut is not a safe-isolation procedure. The two datasets have no invented cross-mapping, and no synthetic Chinese-network readings are attached to the foreign BIM or network.

## Sources and transformations

### Mechanical BIM

**Attribution:** BSI (2020) "Duplex Apartment Test Files," buildingSMART International. [Pinned source directory](https://github.com/buildingsmart-community/Community-Sample-Test-Files/tree/7ddf57a201f88a0c213d5322b02ed15e94a60a40/IFC%202.3.0.1%20(IFC%202x3)/Duplex%20Apartment). Licensed [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/), as stated in the source directory README and retained licence.

Original file: `Duplex_MEP_20110907.ifc`. SHA-256: `13976a8e223f177a6d7123679e4b02e750cd90c13f7bb20c593be125d9407119`.

The source is a public coordination benchmark with building services, not a district-heating station or manufacturer-certified equipment assembly. Its BIM shapes are coordination-level: do not infer fabrication tolerances, hidden pump internals or product suitability from them.

Conversion used **IfcOpenShell 0.8.5** locally, with world-coordinate tessellation in metres. IFC Z-up coordinates were rotated into glTF Y-up by `(x, y, z) → (x, z, −y)`, preserving distances and handedness. Geometry was not redrawn or generated by an image model. The conversion assigns class-based display materials and derives normals; this is not a claim about real surface finishes. Source properties and identities were retained in JSON and GLB extras.

Inspection results: **926 represented IFC elements converted, zero failures**. Counts: 427 flow segments, 358 flow fittings, 105 terminals, 16 energy-conversion devices, 14 controllers, 4 flow-moving devices and 2 distribution-control elements. The source contains **zero explicit port-to-port connections**; the UI reports that absence. Visual adjacency is not treated as connectivity.

### District network

**Attribution:** Roberto Boghetti and Jérôme Kämpf, [OpenDHN data](https://zenodo.org/records/10793816), CC BY 4.0. See also their 2023 benchmark paper cited by the source README. Retained files include the source README and the derived JSON graph.

The imported archive provides **1,352 nodes, 1,362 pipe edges, two heating plants and 150 substations**. Conversion changes serialisation and rotates plan coordinates to the viewer's Y-up convention; it does not invent topology or pipe properties.

The published node layout is anonymised, its elevations are zero, and source route lengths differ from node-to-node chords. Pipe cylinders are therefore **topology glyphs**, with exaggerated widths for selection—not surveyed 3D pipe solids. Surface measurement is disabled on this dataset. The inspector uses the published pipe length, not a length measured from its displayed line.

## Data and deployment boundaries

- Default `/`: imported engineering model and independent network benchmark.
- `/reference`: image-backed Chinese secondary-network simulation and OpenRouter investigation.
- `/operations-classic`: prior procedural Three.js workspace.
- `/legacy`: frozen original research application.

All public assets are shipped through the existing Render/Docker build. The largest GLB is approximately 24 MiB; its JSON property register is approximately 2.5 MiB. The current viewer is not a streaming/LOD BIM engine and has not been certified for very large federated models.

Local GLB files, up to 50 MiB, stay in browser memory. The importer accepts self-contained uncompressed binary glTF 2.0 and rejects external buffer/image URIs and unsupported Draco/Meshopt requirements. GLB metre units and imported names are conventions, not independent verification of the author's scale or identities. Local imports without source property sets do not gain invented IFC metadata. Embedded image textures require `blob:` in the existing `img-src` policy; scripts and network connections remain same-origin.

Viewpoints, notes, imported models and review measurements are in-memory. Export a review before navigating/reloading. This release does not add server-side model storage, issue collaboration, role-based access control, telemetry ingestion or field actuation.

## Reproduction

Use a separate conversion environment; the running app does not need these packages:

```sh
python3.12 -m venv /path/to/conversion-venv
/path/to/conversion-venv/bin/python -m pip install ifcopenshell==0.8.5
/path/to/conversion-venv/bin/python scripts/convert-engineering-assets.py ifc /path/to/Duplex_MEP_20110907.ifc public/engineering-assets
python3 scripts/convert-engineering-assets.py network /path/to/opendhn-data.zip public/engineering-assets
```

The reference IFC conversion command checks the pinned source checksum before using its public-source attribution. It must not be used to misattribute a different IFC file. For other IFC sources, use a separately reviewed conversion with correct attribution/metadata, or [IfcOpenShell/IfcConvert](https://docs.ifcopenshell.org/ifcopenshell-python/geometry_processing.html) to export a self-contained GLB for local inspection. Preserve metre scale and source identities.

## Validation

- TypeScript and production Vite build.
- `npm run test:engineering`: GLB/manifest identity matching, finite geometry bounds, all source records, graph connectivity, loops, outages, path lengths and malicious/unsupported GLB rejection.
- `BASE_URL=http://127.0.0.1:3101 npm run test:engineering:browser`: real orbit gestures and keyboard controls, source-asset selection, focus/isolation, section slider, actual mesh-surface measurements, saved viewpoints, notes/review export, network outage UI, mobile overflow and local GLB import.
- Existing P0, Node/API and Python adapter tests remain applicable to the separate simulator. No live paid AI call is needed for engineering-view verification.

## Before operational reliance

Obtain the installation's as-built GIS/BIM/CAD, reconcile persistent asset IDs and actual hydraulic connectivity, add approved equipment parameters/curves, validate telemetry timestamps and quality, calibrate the physics model, and provide durable identity, auditing and independent protective controls. Survey and engineering acceptance determine precision—not the number of decimal places in the viewer.
